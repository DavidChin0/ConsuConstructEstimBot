## 2026-07-26 — Pipeline Viewer: Revit → IFC → GLB con identidad por elemento

- [2026-07-26] [Opus]: **Reemplazo del pipeline de geometría del Viewer 3D.** El camino viejo era Revit → OBJ (`DB.OBJExportOptions` en `PYREVIT_S10_export_viewer_glb.py`) → obj2gltf → GLB (`viewer_postprocess.py`). El exportador OBJ nativo de Revit **fusiona geometría por material/tipo**, así que la identidad por elemento se perdía antes de que cualquier metadata pudiera engancharse: 2344 instancias entraban y salían ~304 mallas anónimas. Por eso `viewer.html` cruzaba el dump contra el GLB por match de STRING de nombre de tipo (3 estrategias en cascada en `loadGlb()`), frágil y silenciosamente incompleto — y por eso 189 de esas 304 mallas colapsaban en un bbox de 2.0×8.7×6.1m sobre el origen mientras las otras 115 quedaban a ~804m (hallazgo de la ronda anterior).

  **Hallazgo que habilitó el cambio:** el export IFC de Revit SÍ conserva identidad. Verificado sobre un IFC4 real exportado del modelo abierto: cada elemento trae `GlobalId` estable, `Tag` con el ElementId crudo de Revit, y `Name` en formato `Familia:Tipo:ElementId`. Ejemplo real: `#1383=IFCWALL('0wwlg0cxr2TeUR9tNDn3Dj',#6,'Muro básico:AB - Plycem+SteelFraming+Tablayeso:2513884',$,$,#1339,#1344,'2513884',.NOTDEFINED.)`. Con eso el join contra `dump.objects[].id` / `dump.all_instances[].id` pasa de comparación de strings a comparación de enteros exacta.

  **Scripts nuevos:**
  - `backend/scripts_runner/ifc_to_glb.py` — tesela el IFC con ifcopenshell 0.8.5 y emite **un nodo glTF por elemento**, con `name` = ElementId (compatible con la "Strategy 2" que `viewer.html` YA tiene, así que funciona sin tocar el viewer) y `extras` con keynote/categoría/nivel/familia/tipo/type_mark fusionados del full dump. `use-world-coords=True` hornea el placement de cada instancia — que es exactamente lo que el export OBJ estaba perdiendo.

Resuelve el nombre del proyecto preguntándole al MCP por el documento activo.

Revit usa el codepage ANSI del sistema para leer keynote.txt — con ANSI=UTF-8, un archivo Latin-1 (1 byte por acento) se decodifica mal, produce bytes huérfanos, Revit muestra glifo de reemplazo para CADA acento.
